# Held-out set labelling protocol

Status: machinery built in the hardening round (2026-10-23); the data
itself is owner-supplied. This document is the contract the labelling
work must follow before any precision number may be reported.

## Purpose

The golden set (`src-tauri/tests/assist/golden.json`) is a SMOKE TEST
(see DECISIONS, hardening round): it guards against engine regressions.
It is NOT evidence of precision. Precision claims require a frozen,
labelled, held-out set that the checker has never seen during
development. This protocol defines how that set is built so the labels
cannot be tuned against the checker's known behavior.

## Rules (numbered; cite them by number in review)

1. **Labels before checker runs.** Every `labels` entry is written from
   the sentence text alone, before the sentence is ever passed through
   the checker. If a sentence's labels are revised after a checker run,
   the sentence and its full label history must be discarded and
   replaced (tuning labels against output is the failure mode this
   rule exists to prevent).
2. **Per-sentence provenance.** Each line carries `source` and
   `license`. Owner-written sentences are `source: "owner"`,
   `license: "owner"`. Sentences taken from public GEC/grammar corpora
   carry the exact license name. **Before any public set is used,
   check its license terms** — several public GEC sets carry
   non-commercial clauses; those sentences may be scored locally but
   are NEVER committed to the repo.
3. **No third-party corpora in the repo.** Public-set sentences are
   downloaded to a local directory by a script and referenced by
   (dataset, id) in the run manifest. Only owner-written sentences and
   the schema live in version control.
4. **Minimum size and shape.** The held-out set has at least 150
   sentences, and every category in the schema's enum has at least 5
   labelled errors (or is explicitly reported as "n too small" in the
   table — an interval over n < 5 is printed but marked unusable).
5. **Scalar offsets.** Label spans use Unicode scalar indices
   (`start` inclusive, `end` exclusive as in `end`-one-past-last, with
   inclusive-overlap matching against checker issues). For Arabic/CJK
   sentences, record the offsets in scalar space; the loader converts
   nothing.
6. **Categories are the engine's.** `grammar`, `spelling`, `clarity` —
   the three the engine emits. A label whose category would require a
   new engine category is out of scope until the engine grows one.
7. **Frozen means frozen.** Once the owner approves a set version, its
   file (and this schema) is hashed into `docs/EVAL/FROZEN.txt` (SHA-256,
   one line per file, generated by `scripts/freeze-eval-file.sh`), and
   CI (`check-eval-freeze.mjs`) fails on any change. A new version is a
   NEW file (`heldout.v2.jsonl`), never an edit of a frozen one.
8. **Reporting.** Results are reported per category as
   n / TP / FP / FN with Wilson 95% intervals for precision and recall
   (`assist::eval`). Bare percentages and comparisons to other tools'
   published numbers are not part of this protocol.

## What the scoring tool consumes

`assist::eval::score_sentence(category, labels, issues)` +
`aggregate` fold a run into the per-category table;
`wilson_interval_95(tp, tp+fp)` gives the precision interval and
`wilson_interval_95(tp, tp+fn)` the recall interval. The matching
policy is span-overlap AND same-category, documented in `eval.rs` and
deliberately simple; if the policy ever changes, the frozen sets must
be re-scored from scratch and both policies' tables reported for the
transition release.
