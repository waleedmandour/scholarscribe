## Headline 1: Upload a manuscript, extract its references, validate them, export them

The Citation Manager previously required the user to provide the
references separately from the draft: either a `.bib` file or a pasted
plain-text reference list, validated against a draft document. Users who
keep their references inside their manuscript (the common case for
researchers — the references section at the end of the .docx) had to
manually copy-paste the references out of the manuscript into the
Citation Manager, which is error-prone and defeats the point of the
audit.

r7 adds a third mode: **"Upload manuscript (.docx)"**. The user picks
their full .docx manuscript; the app:

1. Extracts the full text via the existing
   `docx_reading::extract_text_from_docx` helper.
2. Identifies the references-section heading by walking paragraphs and
   matching the trimmed, lowercased, punctuation-stripped text against
   the canonical set: `references`, `bibliography`, `works cited`,
   `works referenced`, `literature cited`, `reference list`,
   `list of references`.
3. Splits the text at that heading: everything before is the body
   (with in-text citations), the heading and everything after is the
   references section.
4. Parses the references section to BibTeX using the existing
   `plain_ref_parser::convert_plain_to_bib` with the user's selected
   style hint (default Plain = auto-detect).
5. Runs the existing `citation_manager::validate` against the body
   text (NOT the full manuscript, which would include the references
   section and create false "unused references") and the parsed BibTeX.

The new module `src-tauri/src/manuscript_extractor.rs` does the split;
the new Tauri command `validate_docx_manuscript` orchestrates the
end-to-end flow; the new `ManuscriptReport` type bundles everything the
UI needs: body text, raw references text, parsed BibTeX, parse warnings,
parsed entries, and the citation validation report.

### UI affordances

- A "Pick…" button to choose the .docx manuscript.
- A style dropdown (same as paste mode) for re-parsing if auto-detect
  mangles a reference.
- An "Extract references & validate" primary button (auto-fires on
  pick too).
- A collapsible "Show raw extracted references text" block so the user
  can verify the extractor grabbed the right section.
- A warning when no references-section heading was detected (the body
  and references were not split, so the validation may include false
  "unused references").
- The Export menu (see below).

### Edge cases

- If no references-section heading is found, the entire text is treated
  as the body and the references section is empty. The user is warned;
  they can pick a different style or manually paste the references
  using the paste mode.
- Heading text with trailing punctuation (`References.`, `Bibliography:`,
  `Works Cited,`) is matched by stripping trailing punctuation before
  comparison.
- The split is case-insensitive: `REFERENCES`, `References`,
  `references` all match.

## Headline 2: AMA and IEEE numeric reference styles with full heuristics

The Citation Manager's plain-text parser previously supported APA,
MLA, Chicago, Vancouver, and Plain (auto-detect). Two more numeric
styles are common in academic publishing and were missing:

- **AMA** (American Medical Association, used by JAMA and many medical
  journals). Format:
  `Author AA, Author BB. Title. Journal. Year;Vol(Issue):Pages.`
- **IEEE** (Institute of Electrical and Electronics Engineers, used by
  all IEEE journals and conferences). Format:
  `[N] A. Author, B. Coauthor, "Title," Journal, vol. X, no. Y, pp. A-B, Year.`

Both now have full style-specific heuristics, not just labels:

### AMA parser (`parse_ama`)

- Extracts the `Year;Vol(Issue):Pages` signature at the end with a
  dedicated regex. This is more reliable than the generic parser's
  "split on year" approach because AMA's year, volume, issue, and
  pages are all packed into one semicolon-and-colon-delimited token.
- Splits authors / title / journal on the AMA `. ` separator (period +
  space). Authors are comma-separated in the source (no `&` or `and`),
  so the parser joins them with BibTeX's ` and ` separator.
- Falls back to the generic year + pages + volume extractors when the
  `Year;Vol(Issue):Pages` signature is missing (e.g., book chapters).

### IEEE parser (`parse_ieee`)

- Strips the bracketed `[N]` prefix (already done by
  `split_references`'s `num_re` regex which matches `\[\d+\]`).
- Finds the quoted title `"Title,"` and uses its position to split
  authors from the journal/vol/no/pp/year tail.
- Extracts volume, issue, and pages from their labeled fields
  (`vol. X`, `no. Y`, `pp. A-B`).
- Converts IEEE's initials-first author format (`A. Author, B.
  Coauthor`) to BibTeX's last-name-first format (`Author, A. and
  Coauthor, B.`) via the new `convert_ieee_authors_to_bibtex`
  helper. This is needed so `generate_bibtex_key` extracts the
  actual last name as the key prefix, not an initial — without it,
  `J. Smith` would produce the BibTeX key `J2020paper` instead of
  `Smith2020paper`, which would then fail to match in-text
  citations like `(Smith, 2020)`.
- Handles multi-initial tokens like `A.B.` (concatenated initials)
  and `A. B.` (space-separated initials) — both produce BibTeX
  `A. B.`.

### Plain (auto-detect) mode dispatches per-reference

The Plain mode now sniffs each reference's signature and dispatches
to the right per-style parser, including AMA and IEEE:

- If the reference has IEEE's labeled `vol./no./pp.` fields (at
  least two of the three) or a quoted title, use `parse_ieee`.
- If it matches the `Year;Vol(Issue):Pages` pattern, use `parse_ama`.
- Otherwise, use the existing generic heuristic.

This means a mixed-format list (e.g., the user pasted a manuscript
reference list that contains both AMA-style medical references and
IEEE-style engineering references) parses correctly without the user
having to pick one style and lose the other.

### Tests

Six new Rust tests in `src-tauri/src/plain_ref_parser.rs`:

1. `parses_ama_references_with_year_vol_issue_pages_pattern` — 3 AMA
   references, asserts the Year;Vol(Issue):Pages signature is parsed
   cleanly, authors are joined with ` and `, the BibTeX key starts
   with the first author's last name + year.
2. `parses_ieee_references_with_quoted_title_and_labeled_fields` — 3
   IEEE references with `[N]` prefix, asserts the quoted title is
   extracted, the labeled vol/no/pp fields are parsed, the year is at
   the end, and the BibTeX key starts with the actual last name
   (not the initial).
3. `ieee_author_conversion_handles_multi_initials` — `A.B. Smith, C.
   Jones` → `Smith, A. B. and Jones, C.`.
4. `plain_auto_detect_sniffs_ama_and_ieee_per_reference` — a mixed
   list of 3 AMA + 3 IEEE references parses as 6 entries, each
   dispatched to the right per-style parser.
5. `ama_without_year_vol_pages_signature_falls_back_gracefully` — an
   AMA reference without the signature (e.g., a book chapter) still
   parses without panicking.
6. `ieee_reference_without_quoted_title_records_warning` — an IEEE
   reference missing the quoted title records a warning rather than
   panicking; the vol/no/pp/year fields are still extracted.

All 6 tests pass in the standalone repro binary that copies the
`parse_ama` / `parse_ieee` / `sniff_style` /
`convert_ieee_authors_to_bibtex` logic verbatim and uses the same
`regex` and `serde` crates the project depends on.

## Headline 3: Export menu — Download .bib, Copy BibTeX, Export Markdown report

The user explicitly asked for "a button for options including exporting
the list of references to a BibTeX file". r7 adds an "Export options ▾"
dropdown (a native `<details>` element, no extra JS state) at the
bottom of the Citation Manager results, with three actions:

1. **Download .bib file** — saves the parsed BibTeX (from paste or
   manuscript mode) to a `.bib` file via the browser's Blob + anchor
   download (same approach as the existing `.bib` download in paste
   mode, now also available in manuscript mode).
2. **Copy BibTeX to clipboard** — same content, quick paste-into-
   Overleaf use case.
3. **Export validation report as Markdown** — generates a Markdown
   file with the source, summary stats (Bib entries / in-text
   citations / undefined / unused), the undefined citations table,
   the unused references table, and the per-reference citation counts
   table. Suitable for sharing with co-authors or attaching to a
   peer-review submission. Works in ALL modes (bib_file, paste,
   manuscript) — the report is the validation result, not the
   references, so the user can export it even in bib_file mode where
   they already have a .bib.

For `bib_file` mode, only the Markdown report option is offered (the
user already has a .bib file, so downloading the same content again
would be redundant).

## Headline 4: Per-reference Copy BibTeX + Re-parse with style

Two bonus features the maintainer selected:

- **Per-reference Copy BibTeX button.** Each row in the citation-counts
  table now has a small "Copy" button. Clicking it copies just that
  @entry's BibTeX to the clipboard (e.g., `@article{Smith2020great,
  author = {Smith, J. and Jones, K.}, ...}`). The frontend helper
  `bibEntryToBibtex` mirrors the Rust `entries_to_bibtex_string`
  function so the per-entry output matches what the .bib download
  would contain for that single entry. Useful when the user wants to
  grab one reference to paste into Overleaf or share with a co-author
  without downloading the whole .bib.

- **Re-parse with style button.** When auto-detect mangles a reference
  (e.g., splits authors wrong, misses the year, extracts the wrong
  journal), the user picks a different style from the dropdown and
  clicks "Re-parse with style". In manuscript mode, this re-extracts
  the references from the .docx and re-parses with the new style (the
  manuscript path is stored, no re-upload needed). In paste mode, it
  re-converts the pasted text with the new style (no re-paste needed).
  Both modes re-validate against the draft automatically.
