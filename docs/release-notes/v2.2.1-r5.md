# v2.2.1-r5 (Pre-release)

Released: 2026-10-13. Base version 2.2.1, fifth pre-release revision (r5),
published as a pre-release awaiting maintainer approval. Machine version
fields stay numeric `2.2.1` (Windows MSI constraint); the r5 identity travels
with the tag and release name (see docs/DECISIONS.md).

## Headline: Language Check

ScholarScribe now includes an offline language checker with proposed
corrections, covering spelling, grammar, and style. It does the job Grammarly
is known for with the opposite trust model: Grammarly sends your text to its
servers; ScholarScribe embeds the checking engine in the app process, so the
text is analyzed in memory on your machine and never leaves it. No account,
no upload, no new network hosts. The network-surface CI test proves the host
list is unchanged.

The engine is harper-core (Automattic, Apache 2.0), pinned to an exact
version so upgrades are deliberate events reviewed against the upstream
changelog.

## What the feature does

- **Input.** Paste text or import a `.txt`, `.md`, `.tex`, or `.docx` file.
  A dialect selector covers American, British, Canadian, Australian, and
  Indian English and remembers the choice.
- **Review.** One click runs the check and renders an annotated preview where
  every flagged span is underlined in its category color. Clicking an
  underline jumps to the matching card.
- **Decide.** Issues are grouped under Spelling, Grammar, and Style tabs with
  live counts. Each card shows the message, the sentence context, the rule
  that fired, and typed suggestions (replace, insert after, remove). Apply a
  suggestion and the text updates in place, then the page re-checks
  automatically. Apply all is available per category. You can ignore an
  issue for the session, add a flagged word to your personal dictionary, or
  turn the rule off.
- **Export.** Copy the corrected text or save it as a `.txt` file.

## Honest limits

A rule based checker is deterministic but not complete. It can miss errors a
large commercial service would catch, and it can flag correct academic
wording. The dictionary, ignore, and rule settings exist exactly for that.
English only in this release. The personal dictionary is user content: it
persists to disk only when persistence is opted in, and lives in memory for
the session otherwise.

## Engineering notes

- New `language_check.rs` backend module: run, apply, dictionary, settings,
  file import, and text export commands; the engine is cached per dialect
  behind application state; corrections are applied from the rightmost span
  leftward on the Rust side so offsets never drift in JavaScript.
- Ten Rust unit tests pin the engine: fixture sentences with known faults,
  apply arithmetic, span validation, dictionary suppression, rule
  disablement, and Unicode safety.
- The app's `zip` dependency now enables only the `deflate` feature (OOXML
  files are Stored or Deflated), freeing the exclusive `links = "lzma"` slot
  for harper's zip stack.
- Third-party license inventory regenerated; harper-core, harper-brill,
  harper-pos-utils, and harper-thesaurus (all Apache 2.0) are listed.
- Docs updated truthfully: README, USER_GUIDE (21 tabs), USER_MANUAL
  (module 8c), About page (eight modules). Zero em or en dashes in any
  user-facing string.

## Pipeline fix: CHECKSUMS.txt race

The CHECKSUMS refresh used to run inside the Linux build leg, which could
finish before the Windows leg uploaded its installers, producing an
incomplete checksum file (observed on r4 and repaired manually). The refresh
and the minisign signing now run in a dedicated final job that waits for all
four build legs to finish.
